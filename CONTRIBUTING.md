Thank you for your interest in contributing!

Please follow these guidelines to make the collaboration smooth:

1. Create an issue first to discuss larger changes or new features before implementing.
2. Fork the repository and work on a feature branch named `feature/your-topic` or `fix/your-topic`.
3. Keep changes focused and small; one PR per logical change.
4. Run linters and tests before submitting a PR. The project uses `flake8` and `pytest` (if present).
5. Do not commit secrets, API keys, or model weights. Large models should be downloaded via scripts or stored using Git LFS / external storage.
6. Write clear commit messages and a descriptive PR title + body explaining the change and tests performed.

Repository maintainers will review PRs and may request changes.

Optional: add issue/PR templates and a `CODE_OF_CONDUCT.md` if you expect community contributions.
